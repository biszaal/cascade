# Chapters 11-20 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship 100 more levels (chapters 11-20, the forge and light arcs), taking Cascade to 200, with a deliberate difficulty spike at every tenth level and no new rule.

**Architecture:** Composition only. The generator's budget and seed functions move into `scripts/level-budget.ts`, where every chapter-1-10 branch is pinned by tests and chapters 11+ take their own branch. `scripts/generate-levels.ts` gains `--from <n>` and runs one process per chapter. Chapters are authored in `scripts/level-plan.ts` against gate shapes measured at their real production seeds before authoring.

**Tech Stack:** TypeScript, Vitest, tsx, React Native (Expo SDK 57).

**Spec:** `docs/superpowers/specs/2026-09-13-chapters-11-20-design.md`

## Global Constraints

- **Chapters 1-10 must not change.** `assets/levels/chapter-1..10.json` stay byte-identical after any regeneration.
- **No new rule, mechanic, or engine behaviour.** `src/engine/` is not modified.
- **Every generator change is gated on chapter ≥ 11.**
- **No curve assertion in `scripts/levels.test.ts` is edited to fit a result.** If one fails, the numbers go to the owner.
- **Gates:** level 10 of every chapter from 11 on is `beat: 'climax'`, `pick: 1.0`, and at least **8** above its chapter's second-hardest level. Level 9 is a `rest`.
- **Budgets from chapter 11:** `maxNodes` 8M; pool 16, forge gate 24, light gate 48; 60 attempts per pool slot.
- **Every level keeps at least one anchor, every chapter carries face-down tokens, and every chapter has at least six board shapes.**
- **The ten new chapter accents** are distinct from neighbours and the nine token fills; neighbours differ in lightness.
- Run `npm test` before every commit. `npm run typecheck` must show no errors beyond ones already on `master`.

```ts
import { buildPool } from '<repo>/src/engine/generator';

const [ch, idx, colors, capacity, free, hMin, hMax, anchors, hide, poolArg, nodesArg] = process.argv.slice(2).map(Number);
const POOL_SEED_STEP = 7919;
const OLD_STRIDE = POOL_SEED_STEP * (14 * 200 + 1);
const NEW_STRIDE = POOL_SEED_STEP * (48 * 60 + 1);
const seed = 51 * OLD_STRIDE + ((ch! - 11) * 10 + (idx! - 1)) * NEW_STRIDE + 4242;
const pool = poolArg || (idx === 10 ? (ch! <= 15 ? 24 : 48) : 16);
const spec = {
  capacity: capacity!, colorCount: colors!, emptyLanes: free!, hiddenMin: hMin!, hiddenMax: hMax!,
  anchors: anchors!, hideAnchors: hide === 1,
  strategy: (free! >= 2 ? 'deal' : 'reverse') as const, reverseSteps: colors! * capacity! * 4,
};
const d = buildPool(seed, spec, pool, nodesArg || 8_000_000, pool * 60).map((c) => c.difficulty);
console.log(JSON.stringify({ slot: `${ch}.${idx}`, max: d.at(-1), p90: d[Math.round(0.9 * (d.length - 1))], med: d[Math.round(0.5 * (d.length - 1))], all: d }));
```

- [x] **Step 3: Apply the decision rule**

Two findings change the spec's plan, both inside what it allows:

1. **Smelt and Ore swap.** Capacity 3 cannot out-peak Ore (181 against 250), and peaks must rise through an arc. The spec allows swapping two identities within an arc; each name moves with its identity.
2. **Buried anchors raise the ceiling.** At maximum fog, burying more anchors makes a board harder (six buried: 303-315), contrary to the spec's measurement on anchors kept in sight. Light gates escalate by burying more anchors. Temper keeps its anchors in sight (251) so it stays under Alloy (291).

The light arc can out-peak the forge (315 against 291), so the plan proceeds.

- [x] **Step 2: Implement `scripts/level-budget.ts`**

```ts
export function poolSizeFor(chapter: number, plan: LevelPlan): number {
  if (chapter >= FORGE_START) {
    if (plan.beat !== 'climax') return FORGE_POOL;                    // 16
    return chapter >= LIGHT_START ? LIGHT_GATE_POOL : FORGE_GATE_POOL; // 48 : 24
  }
  // ...the original work-based sizes, unchanged
}
export function maxNodesFor(chapter: number, plan: LevelPlan): number {
  if (chapter >= FORGE_START) return 8_000_000;
  // ...unchanged
}
export function attemptsFor(chapter: number, plan: LevelPlan): number | undefined {
  if (chapter >= FORGE_START) return poolSizeFor(chapter, plan) * 60;
  if (!plan.spec.anchors) return undefined;
  return poolSizeFor(chapter, plan) * 200;
}
const STONE_STRIDE = POOL_SEED_STEP * (14 * 200 + 1);
const FORGE_STRIDE = POOL_SEED_STEP * (48 * 60 + 1);
export function seedFor(chapter: number, index: number): number {
  if (chapter <= 5) return chapter * 1_000_003 + index * POOL_SEED_STEP + 4242;
  if (chapter < FORGE_START) return ((chapter - 6) * 10 + index) * STONE_STRIDE + 4242;
  return 51 * STONE_STRIDE + ((chapter - FORGE_START) * 10 + (index - 1)) * FORGE_STRIDE + 4242;
}
```

- [x] **Step 3: Rework `scripts/generate-levels.ts`**

- `generateChapter(chapter)` holds the existing per-level loop unchanged, but numbers ids from `CHAPTERS` (the level counts of every earlier chapter), never from disk.
- `--chapter <n>` (internal) generates one pack. The parent spawns `process.execPath` with `process.execArgv` (which carries tsx's loader) for each chapter ≥ `--from`, `--jobs` at a time (default: cores − 2).
- `writeManifest()` runs only when every child succeeded, lists `CHAPTERS`, and reads each pack for `parTotal`, throwing if a planned pack is missing.
